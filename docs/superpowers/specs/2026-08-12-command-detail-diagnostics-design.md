# 命令详情分析诊断日志设计

## 目标

在不改变命令分析、重试、审批和用户交互行为的前提下，让下一次命令详情分析失败能够从日志中直接区分以下原因：

- 模型输出不是可解析的 JSON 对象；
- JSON 缺少必需字段或字段类型不正确；
- 风险字段互相矛盾；
- 子命令分组数量、顺序或必需内容不符合要求；
- 模型因输出长度限制而停止。

## 方案

为命令详情响应的拒绝异常增加结构化诊断信息。普通分析和紧凑重试失败时，警告日志记录：

- 分析模式、批次起始位置和子命令数量；
- 稳定的失败原因代码，以及不包含模型原文的计数信息；
- 模型名、请求的 `max_tokens`；
- 返回字符数、completion tokens 和 `finish_reason`。

OpenAI 兼容客户端的标准响应对象增加 `finish_reason`，从 `choices[0].finish_reason` 读取。缺少该字段的兼容接口使用空值，不影响现有调用。

JSON 解析错误只记录错误分类及行列位置。结构校验错误使用代码中定义的原因代码，并在数量不符时记录 expected/actual。日志不记录模型原始响应、提示词、完整命令或凭据。

## 兼容性与行为边界

- 保持当前 `response_format={"type":"json_object"}`、两次请求、token 预算和 30 秒超时不变。
- 保持详情成功、部分成功和失败的判定及用户提示不变。
- 兼容不返回 `finish_reason`、usage 或模型名的测试替身及第三方接口。
- `executor.validator` 的调用和日志行为不变。

## 验证

新增测试覆盖 JSON 解析失败、字段校验失败、子命令数量不符和 `finish_reason=length`。测试断言日志包含诊断元数据，同时不包含模型响应正文和命令正文。完成后运行命令详情定向测试及完整测试套件。
